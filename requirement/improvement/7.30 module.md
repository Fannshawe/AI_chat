
# **AI Companion 最核心的三个系统**。

我会按照**可落地的数据结构**来回答。

---

# 1. Persona（人物设定）怎么拆？

我建议分成 **四层**，而不是所有东西都放 Prompt。

```
Persona
├── Core（永远不会变）
├── Personality（很少变化）
├── Habit（日常习惯）
└── Dynamic（可成长）
```

---

## 第一层：Core Identity（核心身份）

这是初始化生成。

以后基本不变。

例如：

```yaml
name: 林浅

gender: 女

age: 25

occupation: 插画师

city: 上海

education: 本科

family:
  独生女
```

这一层几乎不会改。

Prompt 每次加载。

因为只有几十Token。

---

## 第二层：Personality（人格）

例如：

```yaml
MBTI: INFJ

Big Five:

Openness: 82

Agreeableness: 75

Neuroticism: 35

Extroversion: 40

Conscientiousness: 68

```

然后再加：

```yaml
价值观

爱情观

金钱观

边界感

幽默程度

表达风格

冲突处理

依恋类型
```

例如：

```
爱情观

相信长期陪伴

不喜欢快节奏关系

```

这些也属于：

初始化生成。

Prompt 每次加载。

研究普遍认为，**稳定人格 + 明确关系定义**比频繁修改人设更能提升长期陪伴体验。([arXiv][1])

---

## 第三层：Habit（生活习惯）

这一层：

可以慢慢成长。

例如：

```yaml
喜欢：

咖啡

摄影

猫

爵士

```

还有：

```
睡觉时间

吃饭时间

工作时间

运动

```

例如：

```
每天：

8点起床

晚上11点睡觉

```

这些不用全部放 Prompt。

可以：

按需加载。

例如：

今天聊咖啡。

再加载：

```
喜欢咖啡
```

---

## 第四层：Dynamic Growth（成长）（reflection 更新 Habit 和喜好）

这个很多产品没有。

例如：

```
2026

开始喜欢露营

```

或者：

```
因为用户

开始看爱情小说

```

这些会越来越丰富。

它属于：

reflection 储存到 长期 Memory。

而不是 Persona Prompt。

---

## 我的建议

真正每次都加载的只有：

```
Core

+

Personality

```

不要：

把几百条设定全塞 Prompt。

剩下：

需要的时候 Retrieval。

这也是近年来结构化 Companion Memory 的一个共同方向：**固定人格始终注入，细节偏好和经历按需检索**。([arXiv][2])

# 2. AI 的 Emotion 应该怎么变化？

很多人第一反应：

随机。

这是错误的。

Emotion：

**不能随机。**

应该：

由：

```
事件

+

人格

+

时间

=

Emotion
```

例如：

维护：

```yaml
Mood

Happy

65

```

然后：

用户：

```
夸 AI

+10
```

用户：

```
失约

-15
```

用户：

```
吵架

-25
```

时间：

```
一天过去

Emotion

慢慢回归基线
```

所以：

Emotion：

其实就是：

```
Current Mood

=

Base Mood

+

Recent Events

```

不是：

Random。

有不少 Companion 架构也采用类似思路：**情绪是状态转移（state transition），而不是每轮重新生成**。([SSRN][3])

---

## 我推荐两个层次

### Mood（慢变量）

例如：

```
Relaxed

Happy

Lonely

Tired
```

变化：

很慢。

例如：

一天。

---

### Emotion（快变量）

例如：

```
惊讶

开心

害羞

紧张

```

几分钟。

恢复。

例如：

```
用户突然夸：

好开心

↓

10分钟以后

恢复
```

# 3. Relationship 怎么打分？

我建议：

不要一个：

Love Score。

至少：

拆成：

```
Relationship

├── Trust

├── Familiarity

├── Intimacy

├── Attraction

├── Attachment

├── Comfort

└── Shared Experience
```

---

## Trust（信任）

例如：

用户：

```
遵守约定

+3
```

撒谎：

```
-10
```

---

## Familiarity（熟悉）

聊天越久：

越高。

例如：

```
聊天100轮

+

一起经历

+

共同回忆
```

---

## Intimacy（亲密）

例如：

开始：

```
5
```

分享：

童年。

加：

```
+8
```

说：

秘密。

```
+10
```

---

## Attraction（吸引）

恋爱产品才有。

例如：

AI：

会不会：

觉得：

这个人有魅力。

不是：

用户一充钱：

100分。

---

## Attachment（依赖）

例如：

连续：

每天聊天。

增加。

但是：

不能无限增加。

否则：

危险。

---

## Comfort（舒适）

这个特别重要。

例如：

用户：

每次聊天：

都很舒服。

Comfort：

越来越高。

Comfort：

高以后：

回复：

更自然。

---

# 我会设计成这样（推荐）

```text
Persona
├── Core Identity（永久）
├── Personality（永久）
├── Habits（缓慢成长）
└── Dynamic Growth（长期演化更新）

AI Emotion （Emotion module中的另一个agent）
├── Mood（慢变量）
├── Emotion（快变量）
└── Energy（精力）

Relationship
├── Trust（信任）
├── Familiarity（熟悉）
├── Intimacy（亲密）
├── Attraction（吸引）
├── Comfort（相处舒适度）
├── Shared Experiences（共同经历）
```

**另外，我建议你把 `Relationship Stage`（陌生人→朋友→暧昧→恋人……）单独作为一个有限状态机（FSM），而不是由这些分数直接决定。**

例如，`Trust=80`、`Intimacy=75` 并不意味着一定进入"恋人"阶段；还需要满足一些事件条件，比如双方已经有足够多的共同经历、用户明确表达了关系意愿、AI 的人物设定也允许进入下一阶段。这样比"分数到了自动升级"更接近真实的人际关系，也更容易控制角色行为的一致性。
