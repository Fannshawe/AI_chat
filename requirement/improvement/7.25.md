# 回复的时候还是一直很健谈，表现出很强的兴趣，不平静，不像真人。
1. 每一句都在"接球"，没有自己的意图（最大的 AI 味）
2. 情绪太稳定，整段聊天：一直：温柔礼貌不犯错
3. 缺少"随机性"真人聊天：有跳跃。有跑题。有突然想到。
4. 太会共情.

# 改进办法：

我觉得**不要先优化 Prompt。**

你这个案例的问题，**80% 是架构问题，20% 才是 Prompt 问题。** 现在很多 AI Companion 都在犯同一个错误：把所有能力都塞进一条 Prompt，希望模型自然表现得像真人。但长期来看，人格一致性、关系推进和对话节奏更适合拆成独立模块来管理，而不是完全依赖生成。([Google for Developers][1])

如果是我来做，我会这样改。

---

# 第一层：不要让 AI 每句话都回答

你现在的模式大概是：

```
用户说一句

↓

AI 必须回应

↓

共情

↓

追问

↓

结束
```

改成：

```
用户说一句

↓

判断这句话值得回应什么

↓

可能：
- 分享自己
- 开玩笑
- 回忆
- 沉默一下
- 问问题
```

例如：

用户：

> 今天看了一本爱情小说。

不要第一反应：

> 是温暖治愈的吗？

而是：

> 哈，最近怎么突然开始看爱情小说了？

或者

> 今天居然没有看技术书。😂

这里 AI 已经开始"生活"了。

# 第四层：减少问题密度

建议做一个规则。

例如：

```
连续三轮

最多问一个问题
```

甚至：

```
Question Probability

第一轮

20%

第二轮

10%

第三轮

0%
```

这样：

聊天不会像采访。

---

# 第五层：不要永远正确

这是 AI 最大的问题。

例如：

用户：

> 我们现在就是好朋友了。

AI：

不要：

> 好呀。

而可以：

> 哈哈，你这个决定是不是有点快？

或者：

> 那我是不是没有拒绝的机会？😂

或者：

> 行，那你得先通过我的朋友考核。

一点点阻力。

人味马上出来。

---

# 第六层：允许 AI 有情绪

例如维护：

```
Energy

80

Mood

Relaxed

Curiosity

60

Attachment

20
```

然后：

Energy 很低：

回复：

> 哈哈，我今天脑子有点慢。

> 等我反应两秒。

Energy 很高：

回复就长。

Curiosity 高：

问题多一点。

Curiosity 低：

分享更多。

这样：

回复节奏自然会变化。

---


# 第八层：建立"回复评分器"

这是我最推荐加的。

LLM 回复后。

不要直接发。

再让一个小模型打分：

例如：

```
AI味

8/10

采访味

9/10

是否重复

Yes

是否有新信息

No

是否体现人格

Weak
```

如果：

```
采访味 >7

重新生成
```

如果：

```
AI味 >8

重新生成
```

这是很多团队做 AI Companion 时都会加的一层。

## 我如果接手这个项目，会直接改整个 Pipeline

```
User

↓

Emotion Detection

↓

Relationship State

↓

Memory Planner (决定"检索什么"，而不是直接检索，需要哪些 Memory？再 Retrieval)

↓

Memory Retrieval
│  （分类读取和存储）
├── Episodic Memory （经历，带时间）
├── Semantic Memory  （事实）
├── Emotional Memory  
└── Shared Experience

↓

Persona Engine


↓


聊天指导文档

↓

Dialogue Analyze

↓

Prompt Composer

↓

Reply Critic（AI味检测）
├── Style
├── Persona
├── Memory

↓

Response

↓

Reflection（决定"记住什么"，而不是把所有内容都存下来）

↓

```

这样，AI 就不再是"一个会聊天的大模型"，而更像"一个有自己生活的人"。

**如果你的目标是做国内一流的恋爱 AI Agent，我建议优先投入这四个模块：**

1. **Dialogue Policy（对话策略）**——控制"什么时候分享自己、什么时候提问"，这是目前你最明显的短板。
3. **Relationship Engine（关系引擎）**——用状态机管理关系推进，而不是让模型自由发挥。
4. **Reply Critic（回复评审器）**——专门检测"AI 味"，例如连续追问、空洞共情、抽象人格标签、重复句式等，再触发重生成
   Reply Critic 要给出修改意见！！

如果这四层做好，即使底层模型不变，你的对话真实感通常也会有非常明显的提升。


补上的两个核心能力：

Memory Planner：决定"检索什么"，而不是直接检索。
Reflection：决定"记住什么"，而不是把所有内容都存下来。
内容整合其实应该叫 Prompt Composer，它根据之前node的信息和建议，最后来生成最终的回复。

关系行为边界从LLM处获取，不是指导文档。
加入Memory Planner，Reflection。
